# Aura-owned Hypr config

Canonical Hypr ecosystem files for Aura live under `~/.config/ags/hypr/`.

**Compositor config is Lua** (Hyprland 0.55+). The live entry is:

| Path | Role |
|------|------|
| `hypr/hyprland.lua` | Aura entry — requires modules below |
| `hypr/hyprland/*.lua` | monitors, settings, keybinds, execs, … |
| `~/.config/hypr/hyprland.lua` | Thin XDG stub (`package.path` → this tree) |

Colour scheme files and host scripts stay in `~/.config/hypr/{scheme,scripts}/`.

## Layout

```
hypr/
  hyprland.lua                  # compositor entry (canonical)
  application-style.conf        # Qt Quick style (Arch hyprpolkitagent 0.1.x)
  hyprtoolkit.conf              # hyprtoolkit palette (Aura-built polkit agent)
  hyprlock.conf
  hyprpolkitagent/hyprpolkitagent.conf
  systemd/user/hyprpolkitagent.service.d/override.conf
  hyprland/
    vars.lua
    monitors.lua
    env.lua
    settings.lua
    animations.lua
    gestures.lua
    execs.lua
    rules.lua
    keybinds.lua                # includes Aura media / launcher / workspace binds
    user.lua                    # machine overrides (P52, Wacom, …)
    aura-overrides.lua          # optional Keybinds.* RPC output
    waydroid-size.lua           # generated by waydroid-hypr-size-sync.sh
    aura-keybinds.conf          # legacy hyprlang (unused when on Lua)
    execs-aura.conf             # legacy hyprlang (folded into execs.lua)
  pam/
    login-auth
    login
    sddm
    hyprlock
    polkit-1
```

## Fresh install

1. Install: `hyprland`, `hyprpolkitagent`, `hyprland-qt-support`, `hyprlock`, `polkit`, `swaync`
2. Link XDG paths + write the Lua stub:

   ```bash
   ./scripts/aura-hypr-link.sh
   systemctl --user restart hyprpolkitagent
   hyprctl reload
   ```

3. Verify:

   ```bash
   ./scripts/aura-hypr-link.sh --check
   pkexec true
   ```

Edit binds/settings under `hypr/hyprland/*.lua`, then `hyprctl reload`. Do **not** put live compositor Lua under `~/.config/hypr/hyprland/` anymore.

## Polkit agent (hyprtoolkit, not Qt)

Arch `extra/hyprpolkitagent` is still **Qt/QML**. Aura builds the **hyprtoolkit-native** agent from git:

```bash
./scripts/build-hypr-polkit.sh --ensure   # rebuild only if ABI drifted (preferred)
./scripts/build-hypr-polkit.sh            # force rebuild
./scripts/build-hypr-polkit.sh --restart  # ensure + restart user unit
./scripts/aura-hypr-link.sh               # symlinks configs + systemd override
systemctl --user restart hyprpolkitagent
pkexec true
```

`--ensure` is hooked into `hyprland-patched/update.sh`, `sync-hypr-patched.sh`, and the unit’s `ExecStartPre`, so aquamarine/hyprutils SONAME bumps after a Hypr update cannot leave a dead agent. By default the script **bundles hyprtoolkit from git** (API-matched to the agent) while linking aquamarine/hyprutils from the system; an ABI stamp skips rebuilds when nothing changed.

Theming (hyprtoolkit build reads these):

| File | Effect |
|------|--------|
| `hypr/hyprtoolkit.conf` | Colors, fonts, rounding |
| `hypr/hyprpolkitagent/hyprpolkitagent.conf` | Window size, `show_details` |

`application-style.conf` is only for the old Qt package; ignore once the Aura build is active.

## PAM: login vs fingerprint auth

Arch’s default `/etc/pam.d/system-auth` enables **fingerprint before password** everywhere it is included — including TTY `login` and SDDM. Aura splits this:

| Service | Fingerprint | Notes |
|---------|-------------|--------|
| `login` / `sddm` | **No** | Session start requires password |
| `polkit-1` | Yes | Password tried first (no 30s wait) |
| `hyprlock` | Yes | Unlock: password (PAM) + fingerprint (hyprlock native dbus, parallel) |
| `sudo` | Yes | Still uses stock `system-auth` |

Install (backs up existing files under `/etc/pam.d/`):

```bash
sudo ./scripts/aura-pam-install.sh
pkexec true                          # polkit: password works immediately
```

Next TTY or SDDM login will require your password; `sudo` and polkit prompts still accept fingerprint.

## uwsm / systemd

```ini
exec-once = systemctl --user enable --now hyprpolkitagent.service
```

(Already in `hyprland/execs.lua`.) No GTK or KDE polkit agents required.

## Keybind RPC

Preferred edits: `hypr/hyprland/keybinds.lua`.

`Keybinds.*` RPC may write `hypr/hyprland/aura-overrides.lua` (loaded last). Legacy `aura-keybinds.conf` is hyprlang-only and is **not** sourced on the Lua path.

## Lua dispatch note (0.55+)

Classic `hyprctl dispatch workspace N` is rejected on Lua-config builds. Use:

```bash
hyprctl dispatch 'hl.dsp.focus({ workspace = N })'
hyprctl dispatch 'hl.dsp.window.move({ workspace = N })'
```

`~/.config/hypr/scripts/wsaction.zsh` already uses these forms. Workspace number binds in `keybinds.lua` call `hl.dsp` directly.

## Other surfaces

| Surface | Config |
|---------|--------|
| Lock screen | `hypr/hyprlock.conf` (**hyprlang**, not Lua — only the compositor is Lua) |
| Lock wrapper | `scripts/hyprlock.sh` → `~/.local/bin/hyprlock` (flock, HDMI blank, park Waydroid) |
| Aura React/GTK shell | `Settings.theme` in control center |
| Colour scheme | `~/.config/hypr/scheme/` (still written by theme tooling) |

### hyprlock notes

- hyprlock does **not** use Lua. Keep editing `hypr/hyprlock.conf`.
- Invalid options (e.g. `auth:fingerprint:max_attempts` before a patched rebuild) make hyprlock print config errors; remove or rebuild `hyprlock-patched` with that option from `Engineering/Productivity/hyprlock`.
- Duplicate instances abort on `ext-session-lock` and dump cores — the Aura wrapper serializes starts. `hypridle` should use `pidof hyprlock || hyprlock`.
- If hyprlock dies while Hyprland still holds the lock, the wrapper relaunches a few times and `hyprlock-watchdog.timer` restores the UI (needs `session-lock-wanted` marker from the wrapper).
- Waydroid: use `ro.hardware.gralloc=minigbm_gbm_mesa` + `drm_device=/dev/dri/renderD128` (Intel). Wrong `gralloc=default` crash-loops surfaceflinger. Session is `waydroid-session.service` (Aura); lock wrapper soft-parks it during hyprlock only.
